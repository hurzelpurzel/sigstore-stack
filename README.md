# Local Sigstore stack

A self-contained [Sigstore](https://www.sigstore.dev/) stack for **keyless signing
of blobs and container images** on your machine. It runs Fulcio, Rekor, a CT log,
Keycloak as the OIDC issuer, the Rekor search UI, and a local OCI registry with
Docker Compose (or Podman Compose).

Everything here is for **development and testing only**. The CA and log keys are
checked-in dev keys, passwords are in `.env`, and services speak plain HTTP.

New to image signing? Start with [HOWTO.md](HOWTO.md). Coding agents should
read [AGENTS.md](AGENTS.md) first.

## Components

| Service | Purpose | Host address |
| --- | --- | --- |
| Fulcio | Issues short-lived code-signing certificates | http://localhost:5555 |
| Rekor | Transparency log for signatures | http://localhost:3000 |
| Tesseract | Certificate Transparency log used by Fulcio | http://localhost:6962 |
| Keycloak | OIDC issuer (`sigstore` realm), demo user `alice` | http://keycloak.localhost:8080 |
| Rekor UI | Search/browse Rekor entries | http://localhost:8081 |
| Registry | Local OCI registry for image signing demos | http://localhost:5001 |
| MySQL | Trillian storage and Rekor search index | internal |
| Trillian | Rekor's append-only log backend | internal |

The OIDC issuer used in certificates is
`http://keycloak.localhost:8080/realms/sigstore`. `*.localhost` resolves to
loopback on the host, and `keycloak.localhost` is also a network alias inside
Compose, so the same issuer URL works from both sides.

## Prerequisites

- Docker with Compose v2, or Podman with `podman-compose`
- `cosign` v3 or newer
- `curl` and `jq` for the helper scripts
- `podman` or `docker` for the image demo

## Quick start

```bash
cp .env.example .env
make up
make demo
```

`make demo` signs and verifies a temporary file, then builds and pushes a tiny
image to the local registry, signs it, and verifies it.

Keycloak's admin console is at http://keycloak.localhost:8080/admin
(`admin` / `admin`), and the demo signing user is `alice` / `alice`
(email `alice@example.com`).

Rekor entries can be browsed at http://localhost:8081.

## Sign a blob

```bash
make sign-blob FILE=./release.tar.gz
make verify-blob FILE=./release.tar.gz
```

The bundle is written to `./release.tar.gz.sigstore.json`. The helper obtains an
OIDC token from Keycloak with the demo user's password grant. To use your own
token:

```bash
./scripts/sign-blob.sh --identity-token "$(./scripts/token.sh)" ./release.tar.gz
```

Equivalent raw cosign command:

```bash
TOKEN=$(./scripts/token.sh)

cosign sign-blob --yes \
  --signing-config config/cosign/signing-config.json \
  --trusted-root config/cosign/trusted-root.json \
  --bundle release.tar.gz.sigstore.json \
  --identity-token "$TOKEN" \
  release.tar.gz

cosign verify-blob \
  --bundle release.tar.gz.sigstore.json \
  --trusted-root config/cosign/trusted-root.json \
  --certificate-identity alice@example.com \
  --certificate-oidc-issuer http://keycloak.localhost:8080/realms/sigstore \
  release.tar.gz
```

## Sign a container image

```bash
# Builds/pushes a demo image and prints IMAGE=repo@sha256:...
make seed-registry

make sign-image IMAGE='localhost:5001/demo/hello@sha256:...'
make verify-image IMAGE='localhost:5001/demo/hello@sha256:...'
```

Always sign the immutable digest (`repo@sha256:...`), not a mutable tag. The
`make seed-registry` target resolves and prints the digest for you.

The image helpers pass `--allow-http-registry` because the bundled registry is
plain HTTP. For manual commands add the same flag.

## Configuration

Defaults live in `.env` (see `.env.example` for all settings). The most useful
values:

| Variable | Default |
| --- | --- |
| `KEYCLOAK_ISSUER` | `http://keycloak.localhost:8080/realms/sigstore` |
| `KEYCLOAK_DEMO_USER` / `KEYCLOAK_DEMO_PASSWORD` | `alice` / `alice` |
| `FULCIO_URL` | `http://localhost:5555` |
| `REKOR_URL` | `http://localhost:3000` |
| `REGISTRY` | `localhost:5001` |

`config/cosign/trusted-root.json` and `config/cosign/signing-config.json` are the
cosign v3 trust and service-discovery files generated for these URLs. `cosign`
is run with `--trusted-root` instead of fetching trust material from TUF.

## Regenerating the development PKI

All key material is generated by:

```bash
make pki
```

This creates:

- `config/pki/fulcio.crt.pem` / `fulcio.key.pem` – Fulcio root CA
- `config/pki/rekor.key.pem` / `rekor.pub.pem` – Rekor log signing key (ECDSA P-256)
- `config/pki/ctlog.key.pem` / `ctlog.pub.pem` – CT log signing key
- `config/cosign/trusted-root.json` – trust anchors for cosign
- `config/cosign/signing-config.json` – service URLs for cosign v3

After regenerating, recreate the stack and its data:

```bash
make reset
```

The Rekor log ID is derived from its public key, so old entries no longer verify
against a new key. `make reset` removes the MySQL/Trillian/CT/registry volumes
for a clean log.

## How key persistence works

The Rekor wrapper in `rekor/` waits for MySQL and Trillian, reads the highest
`TreeId` from Trillian's `Trees` table, and starts `rekor-server` with
`--trillian_log_server.tlog_id=<id>`. This reuses the existing transparency log
across container restarts instead of letting Rekor create a fresh tree each
time.

## Development caveats

- **DEV ONLY.** Private keys and passwords are in the repository. Never reuse
  this configuration for anything real.
- Keycloak runs with `start-dev` over HTTP.
- There is no timestamp authority (TSA) configured.
- Fulcio and Rekor are exposed directly on the host without authentication.
- The registry has deletion enabled to make local experiments easier.

## Troubleshooting

**`keycloak.localhost` does not resolve**

On most systems `*.localhost` maps to loopback automatically. Check with:

```bash
getent hosts keycloak.localhost
```

If it does not resolve, add `127.0.0.1 keycloak.localhost` to `/etc/hosts`.
Keep the issuer URL identical on the host and inside the Compose network;
certificates embed it.

**A rebuilt image is not being used**

`podman-compose` sometimes keeps an existing container after an image rebuild:

```bash
podman rm -f sigstore-stack_rekor-server_1
podman-compose up -d --force-recreate rekor-server
```

A full `make reset` is the simplest fix.

**Signing fails with `not enough verified log entries from transparency log`**

cosign/sigstore-go verifies Rekor v1 SETs with ECDSA. If the Rekor log key is
Ed25519, the SET is skipped. `scripts/gen-pki.sh` generates an ECDSA P-256 key;
regenerate with `make pki && make reset` if you changed it.

**Image push or sign fails with an HTTP/TLS error**

Manual `cosign` commands need `--allow-http-registry`. `podman push` needs
`--tls-verify=false`; the helper scripts already do this.

**Inspect logs**

```bash
make logs
podman-compose logs rekor-server
podman-compose logs fulcio
```

scripts/sign-image.sh        Sign an image digest
scripts/verify-image.sh      Verify an image signature
